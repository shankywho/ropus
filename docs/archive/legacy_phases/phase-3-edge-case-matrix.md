# Phase 3 — Device Intelligence 42-Case Comprehensive Edge Case Matrix

**Document Version:** 1.0 (Edge Case & Test Specification)  
**Total Scenarios Covered:** 42 Deterministic Real-World Fraud & Failure Scenarios  

---

| # | Edge Case Scenario | Expected System Behavior | Risk Implication | Persistence Behavior | Redis Behavior | ML Feature Behavior | Decision Impact | Test Requirement |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **Missing Fingerprint (`null` / empty string)** | Set `device_info_missing = 1`, assign fallback novelty state. | High fraud risk (script bot bypass attempt). | Encrypt empty marker; no row created in `devices`. | Skip device velocity key lookups. | `device_info_missing=1`, `device_seen_before=0`, `device_tx_count_1h=0`. | Triggers `MODEL_SIGNAL:MISSING_DEVICE_TELEMETRY`; pushes towards `MANUAL_REVIEW`. | Unit test: `test_missing_device_fingerprint` |
| **2** | **Whitespace-Only (`"   "`)** | Trim whitespace; treat as missing fingerprint. | Evasion attempt. | Handled as empty string. | No keys recorded. | `device_info_missing=1`. | Evaluates as missing device. | Unit test: `test_whitespace_fingerprint` |
| **3** | **Malformed / Short String (`"abc"`)** | Reject format; set `device_info_missing = 1`. | Client tampering / bot error. | Stored in `raw_payload`; skipped in device registry. | No velocity increment. | `device_info_missing=1`. | Low trust penalty. | Unit test: `test_short_fingerprint` |
| **4** | **Oversized String ($> 256$ chars / Buffer Overflow)** | Truncate and SHA-256 hash safely; reject invalid lengths. | DOS / Injection attempt. | Payload sanitized before JSON marshaling. | Tenant hash generated on valid prefix. | `device_info_missing=1`. | Log security warning; flag review. | Security test: `test_oversized_payload` |
| **5** | **SQL Injection in String (`"' OR 1=1;--"` )** | Parameterized SQL queries in Go `pgx`; SHA-256 hash generated safely. | Active exploit attempt. | Safe parameterized insertion in `risk_decisions`. | Redis string key safe from injection. | Standard feature vector. | Pre-rule or sanitize layer passes clean hash. | Security test: `test_sql_injection_device_field` |
| **6** | **First-Ever Device Observed Globally** | Create new `devices` row; record `first_seen_at = now()`. | Unverified baseline novelty. | Insert row into `devices` with `total_tx_count=1`. | Set `{tenant}:dev:known:{hash}` with 90d TTL. | `device_seen_before=0`, `device_age_days=0.0`. | Standard evaluation based on amount & velocity. | Integration test: `test_first_seen_registration` |
| **7** | **Known Device with Single Linked Account** | Update `last_seen_at = now()`, increment `total_tx_count`. | Low risk / trusted established hardware. | Update `devices` and `device_accounts` timestamps. | Increment sliding window sorted sets. | `device_seen_before=1`, `device_unique_accounts_24h=1`. | Eligible for `ALLOW_RECOMMENDATION`. | Integration test: `test_known_device_single_account` |
| **8** | **Device Returning After 90+ Days Inactivity** | Recognize device; calculate `device_last_seen_age_days >= 90`. | Moderate risk (dormant account reactivation / recycled hardware). | Update `last_seen_at`. | Repopulate Redis cache from PostgreSQL. | `device_seen_before=1`, `device_age_days=90+`. | Appends `MODEL_SIGNAL:DORMANT_DEVICE_REAPPEARED`. | Integration test: `test_dormant_device_return` |
| **9** | **Device Shared by 2 Accounts (Household)** | Link second account in `device_accounts`. | Normal benign consumer behavior. | Insert row into `device_accounts`. | `SCARD {tenant}:dev:acc24` returns `2`. | `device_unique_accounts_24h=2`. | Low score impact if velocities are normal. | Integration test: `test_dual_account_sharing` |
| **10** | **Device Shared by 20 Accounts (Corporate/Campus)** | Increment account count; monitor token diversity. | Medium risk (shared terminal or credential stuffing). | 20 linked rows in `device_accounts`. | `SCARD {tenant}:dev:acc24` returns `20`. | `device_unique_accounts_24h=20`. | Pushes expected loss above review threshold. | Integration test: `test_multi_account_threshold` |
| **11** | **Device Shared by 100 Accounts (Fraud Farm)** | Trigger pre-rule or hard policy threshold for multi-accounting. | Critical risk (organized fraud botnet / emulator). | Flag device in `device_reputation`. | Set `{tenant}:dev:bad_rep`. | `device_distinct_accounts_all_time=100+`. | Immediate `DECLINE_RECOMMENDATION` or `MANUAL_REVIEW`. | Rule test: `test_fraud_farm_device_block` |
| **12** | **Single Account Using 20 Devices in 1 Hour** | Ingest distinct device hashes for single account. | Critical risk (Account Takeover / distributed attack). | 20 distinct `device_accounts` linkages created. | `{tenant}:acc:devs1h:{account}` count = 20. | `account_device_velocity_1h=20`. | Immediate `STEP_UP_RECOMMENDATION` (MFA/3DS). | Integration test: `test_account_device_spray` |
| **13** | **Device Used with 10 Distinct Payment Cards in 1h** | Track distinct payment tokens on device. | Critical risk (Card Testing / BIN Attack). | 10 rows in `device_payment_instruments`. | `SCARD {tenant}:dev:tok24` = 10. | `device_unique_tokens_24h=10`. | Triggers `RULE_SIGNAL:HIGH_TOKEN_VELOCITY_24H` -> `DECLINE`. | Integration test: `test_device_card_testing` |
| **14** | **Single Card Token Used Across 10 Distinct Devices** | Query token-to-device mapping. | Stolen card broadcast attack. | 10 device linkages on same payment token. | `{tenant}:tok:devs1h:{token}` count = 10. | `token_device_velocity_1h=10`. | Decline subsequent authorization attempts. | Integration test: `test_token_distributed_attack` |
| **15** | **Device Associated with Prior Confirmed Fraud** | Query `device_reputation`. | Confirmed malicious hardware. | `confirmed_fraud_count > 0` in `device_reputation`. | SISMEMBER in bad reputation set = `1`. | `device_fraud_associated=1`. | Pre-rule triggers immediate hard `DECLINE`. | Rep test: `test_confirmed_fraud_device_block` |
| **16** | **Device Associated with Prior Chargeback Dispute** | Query dispute ledger. | High financial risk (friendly fraud or chargeback risk). | `chargeback_count > 0`. | Bad reputation cache hit. | `device_fraud_associated=1`. | Routes to `MANUAL_REVIEW`. | Rep test: `test_chargeback_associated_device` |
| **17** | **Device Used < 5m After Password Reset** | Cross-reference account auth event timestamps. | High ATO risk (Account Takeover execution). | Record auth event in `device_events`. | Auth event cached in Redis. | `time_since_password_reset_mins < 5`. | Routes to `MANUAL_REVIEW` / Step-up. | Integration test: `test_ato_password_reset_flow` |
| **18** | **First-Seen New Device + High Amount (₹100k+)** | Detect new device with large ticket size. | High risk (large extraction on compromised credentials). | Created as new device. | Zero historical velocity. | `device_seen_before=0`, `amount=100000`. | Beta model output $>0.35$ -> `DECLINE` / `REVIEW`. | ML test: `test_new_device_high_amount` |
| **19** | **First-Seen New Device + High IP Velocity** | Correlate IP burst with novel device. | Botnet rotation / proxy hopping. | New device created. | IP velocity $\ge 5$. | `device_seen_before=0`, `ip_velocity_1h=5`. | Policy action: `DECLINE`. | Pipeline test: `test_new_device_high_ip_vel` |
| **20** | **Known Device + Extreme Amount Anomaly vs User Mean** | Compare current amount to `amount_to_mean_ratio`. | Compromised user session or unusual purchase. | Normal device update. | Device recognized. | `device_seen_before=1`, `amount_to_mean_ratio=8.5`. | Routes to `MANUAL_REVIEW` (24h SLA). | Policy test: `test_known_device_amount_anomaly` |
| **21** | **FingerprintJS Blocked by Ad-Blocker (uBlock)** | Graceful degradation; client sends fallback token. | Missing client entropy. | Stores fallback token. | No device registry update. | `device_info_missing=1`. | Fallback to IP & Card Token velocities. | Client test: `test_adblocker_blocked_telemetry` |
| **22** | **FingerprintJS Execution Timeout on Frontend** | Frontend client times out after 2s; submits fallback ID. | Slow client network. | Handled as fallback hardware hash. | Standard processing. | `device_info_missing=1`. | Evaluates without blocking transaction. | Client test: `test_fingerprintjs_timeout` |
| **23** | **Duplicate Request Submitted (Idempotency Key Match)** | Return cached previous decision from PostgreSQL. | Network retry / duplicate submission. | Return existing `decision_id` without re-scoring. | No double-counting in Redis velocity. | Unchanged. | Returns identical decision immediately. | API test: `test_duplicate_idempotency` |
| **24** | **Replayed Device Fingerprint from Foreign ASN / Country** | Compare IP Geo/ASN against device historical ASNs. | Remote proxy attack / replayed stolen visitorId. | Record event with new IP. | Flag geo-anomaly in Redis. | `device_asn_anomaly=1`. | Elevates risk score -> `MANUAL_REVIEW`. | Integration test: `test_replayed_fingerprint_geo_mismatch` |
| **25** | **Concurrent First-Seen Requests (< 10ms Apart)** | PostgreSQL atomic `ON CONFLICT DO NOTHING` + Redis `SETNX`. | Distributed race condition. | Single row created in `devices`. | Redis locks ensure atomic counter initialization. | Both receive clean first-seen features. | Consistent decisioning. | Concurrency test: `test_concurrent_first_seen_race` |
| **26** | **Concurrent Transactions on Same Device Across Merchants** | Scoped strictly per tenant ID. | Multi-merchant card testing. | Separate records under respective `tenant_id`. | Keys quarantined by `{tenant_id}:...`. | Independent feature extraction. | No cross-tenant data leakage. | Multi-tenant test: `test_concurrent_multi_merchant` |
| **27** | **Browser Update Changes Canvas/WebGL Hash (Hash Drift)** | Treat as novel device initially; link via account history. | Legitimate browser version upgrade. | New device created; linked to existing `account_id`. | New device hash registered. | `device_seen_before=0`, `account_has_prior_history=1`. | Low friction if account & token match historical norm. | Lifecycle test: `test_browser_update_hash_drift` |
| **28** | **OS Update Changes Font Subsystem Metrics** | New visitor ID generated for physical machine. | Benign system maintenance. | Stored as new device. | Redis records new device. | `device_seen_before=0`. | Mild novelty penalty. | Lifecycle test: `test_os_update_font_drift` |
| **29** | **User Switches from Standard Mode to Incognito** | FingerprintJS preserves Canvas/WebGL hash in Incognito. | User privacy mode. | Device recognized. | Redis cache hit. | `device_seen_before=1`. | Seamless frictionless authorization. | Browser test: `test_incognito_persistence` |
| **30** | **Mobile iOS Safari (Shared Hardware Specs)** | Recognize low-entropy mobile user-agent; rely on IP/Token. | High false positive risk if device treated as unique user. | Record device. | Redis tracks mobile device velocity. | `device_type_mobile=1`. | Model applies lower weight to mobile device novelty. | Mobile test: `test_ios_safari_collision_mitigation` |
| **31** | **Multiple Browsers on Same Laptop (Chrome + Firefox)** | Produces 2 distinct visitorIds for single physical machine. | Multi-browser power user. | 2 distinct device rows linked to same `account_id`. | 2 independent Redis keys. | Both linked to account. | Normal behavior. | Multi-browser test: `test_multi_browser_same_machine` |
| **32** | **User on Commercial VPN (Mullvad) on Same Device** | IP changes rapidly while device fingerprint remains fixed. | Privacy-conscious user or fraudster hiding IP. | Record new IP in `device_events`. | IP velocity low; Device velocity tracks true usage. | `device_seen_before=1`, `ip_is_vpn=1`. | Moderate score elevation. | Network test: `test_vpn_device_stability` |
| **33** | **Corporate NAT: 500 Employees on Single Public IP** | IP velocity extremely high; device fingerprints distinct. | High false positive risk if only relying on IP velocity. | 500 distinct device records. | IP velocity high; individual device velocity = 1. | `ip_velocity_1h=500`, `device_tx_count_1h=1`. | **Device intelligence prevents false declination of corporate users!** | Network test: `test_corporate_nat_isolation` |

| **36** | **Deleted Device Record in PostgreSQL (Stale Cache)** | Redis TTL expires; DB query returns not found -> recreated. | Database administrative cleanup. | Recreates device record cleanly. | Key repopulated upon recreation. | Treated as first-seen. | Fails safe. | Resilience test: `test_stale_cache_resilience` |
| **37** | **Expired Velocity Record in Redis (> 24h Window)** | Redis sorted set prunes entries; returns count = 0. | Normal sliding-window expiration. | Historical counts preserved in PostgreSQL. | Redis memory remains bounded and compact. | `device_tx_count_24h=0`. | Clean baseline. | Redis test: `test_redis_ttl_window_pruning` |
